# 01 · 設計決策與修正

原計劃嘅框架係好嘅 —— 視覺為主、步驟少、無壓力、獎勵過程多過結果。
以下記錄喺實作過程中發現嘅問題同改法，按嚴重程度排序。

---

## 🔴 A 級：會直接打倒誠信教學目標（已修）

### A1. 機器人提早洩漏答案

> **原計劃**：「畫面 3 核對 → 小機器人反應：**一樣就笑；唔一樣就「咦」**」

**點解唔得**：畫面 4 嘅目的係學生**自己決定**「一樣定唔一樣」。
如果畫面 3 機器人已經笑咗／「咦」咗，學生揀「一样」只係抄答案，
而揀「唔一樣」只係扮唔知。兩個都唔係誠實。

**改法**：機器人由畫面 2 到畫面 3 **全程中性**。
- 只做「提問」：`呢個嘢，清單上面有冇？`
- 唔做「判斷」：無笑、無「咦」、無 ✅/❌
- 對錯反應**只喺畫面 4 學生答完之後**先出現

實作：`FACES` 只有 `neutral / happy / think / thanks`；
`say(text, "neutral")` 係畫面 2、3 唯一用嘅表情。

---

### A2. 畫面 3 同畫面 4 問同一條問題

> **原計劃**：畫面 3「配對相同圖，**或選擇「一樣」**」→ 畫面 4「你取嘅同清單一樣嗎？選擇**「一樣」或「唔一樣」**」

**點解唔得**：連續問兩次同一個二選一，學生第二次只會重複第一次嘅按掣。
變成測記憶，唔係測判斷。而且學生會發現「答錯咗都冇事」→
變成亂撳。

**改法**：兩個畫面問**唔同層級**嘅問題

| | 問題 | 層級 | 教咩 |
|---|---|---|---|
| 畫面 3 | 「呢個嘢，清單上面有冇？」（逐件問） | 技能 | 「一樣 / 唔一樣」呢個概念 |
| 畫面 4 | 「你攞嘅嘢，同清單一樣嗎？」（成張單問一次） | 價值觀 | 如實交代 |

畫面 3 每件問一次（3 件 = 3 輪），畫面 4 只問一次。

---

### A3. 三個隱性洩漏位

原計劃講「核對結果用顏色 + 表情即時回饋」。**「即時」就係問題**。
實作時發現三個位會偷偷洩漏：

| 位 | 原本 | 點解漏 | 已改 |
|---|---|---|---|
| 放大檢視面板 | 顯示 `✅`（喺清單上）/ `❓`（唔喺） | 直接話咗答案 | 淨係顯示放大嘅圖，冇任何標記 |
| 已核對項目底色 | 綠色（`--ok-soft`） | 綠色 = 「啱」，學生會咁讀 | 改中性藍灰 `#E6EDF3`，純粹表示「睇過」 |
| 逐項核對回饋 | 答完即時顯示對/錯 | 學生跟住答案填，冇喺核對 | 完全冇即時回饋，全部留到畫面 4 之後 |

---

### A4. 「完成就有星星」會令亂答都得分

> **原計劃**：「無論結果如何，只要完成選擇，就給予星星」

方向啱，但有漏洞：**一個學生連續 3 次都撳「一樣」，可以攞晒 3 顆星**，
系統分唔出「自己睇過」同「亂撳」。對中度智障學生呢個係常見情況。

**改法**：星星維持**非懲罰性**（唔會因答錯扣星星，呢點要保留），
但加一個**老師用嘅數據源**：

- 網頁右上角「老師」掣 → 自動記低每張單嘅
  `攞到咩 / 漏咗咩 / 多咗咩 / 逐項核對 / 誠實答覆 / 實際 / 有冇落差`
- 鍵盤 `T` 都叫得，掣做得細，避免學生搶住撳
- 可一鍵複製成文字，貼落觀察記錄

**重點**：星星獎「肯答」，記錄表睇「有冇自己睇過」。
兩件事分開，老師先有得教。

---

### A5. 答錯唔可以被 punish

**改法**：四種結果全部有正面回應，**冇一種講「你講錯」**

| 學生答 | 實際 | 系統講 |
|---|---|---|
| 唔一樣 | 唔一樣 | 「**多謝你老實講！**」＋漏／多 ＋「付足、講足」 |
| 一樣 | 一樣 | 「一樣晒，**付足啦**！自己對清楚再講，就係付足錢。」 |
| 一樣 | 唔一樣 | 「**多謝你講。**下次對清楚先，好似付足錢咁。」 |
| 唔一樣 | 一樣 | 「多謝你咁小心！我哋再對一次。」 |

四種**全部送星星**。誠信 ＝ 肯面對自己睇到嘅嘢，唔係 ＝ 一定答啱。

### A6. 正面訊息被派咗否定色（除錯巡檢發現）

A5 定咗「四種結果全部正面」，但**顏色冇跟住呢條規則行**。

| 學生答 | 實際 | 標題 | 原本顏色 | 問題 |
|---|---|---|---|---|
| 一樣 | 唔一樣 | 「多謝你話我知。」 | `--no` 深紅 `#8F2D00` | 文案正面，色系係懲罰 |
| 唔一樣 | 一樣 | 「你話唔一樣？」 | `--no` 深紅 | 係問句，唔係指責 |

**根因**：顏色係跟 **branch**（行到邊條 code path）派，唔係跟 **sentiment**（學生感受）。「話一樣但實際唔一樣」被歸類做「答錯嗰個 branch」，於是連帶個正面文案都著咗紅色。

對一個**明確設計成四種結果全部正面**嘅教材，色系上嘅懲罰訊號會打倒 A5 嘅設計目標 —— 學生讀到嘅係「系統當我錯」。

**改法**：抽出 `paintResult()`，四個分支嘅文案 + 顏色集中喺一處；顏色只准 `--ok`（綠）或 `--ink`（中性），並喺函數頭寫死紅線註釋，令之後唔會再漂移。

**驗證**：`grep -- --no` 喺結果標題已 0 處，只剩 CSS 變數定義同 `.big.alt` 掣背景（答案選擇鈕本身，唔係回饋）。

## 🟡 B 級：會卡住學生或影響可用性（已修）

### B1. 貨架畫面冇出口掣 —— 學生會卡死

原本由貨架去核對冇任何按鈕，流程斷咗。
加咗 **`✅ 我攞完啦，核對一下`**（96px 高）。

### B2. 空籃會跳去一個冇掣嘅死畫面

按「我攞完啦」而籃係空嘅時候，`renderCheck()` 自動跳去誠實確認，
但之後嗰行 `go("check")` 又跳返核對畫面 —— **學生卡喺一個冇任何嘢可撳嘅畫面**。
（實測捉到，唔係猜。）

**改法**：空籃判斷一定要喺 `renderCheck()` **之前**做，
直接 `go("declare")` 並提早 `return`。

### B3. 核對掣被推到畫面外，要 scroll 先撳到

中度智障學生未必識得 scroll。改咗排版：
放大面板縮成淨係一個大圖 + 兩個按鈕並排，**任何闊度都唔使 scroll**。

### B4. 標題被裁走

`justify-content:center` + `overflow-y:auto` 嘅經典 flexbox bug：
內容一高過容器，頭尾都會被裁走，「貨架」個標題完全見唔到。
改用 `justify-content: safe center`。

### B5. 機器人同購物籃重疊

原本兩個 `position:absolute` 都 bottom-left / bottom-right，
窄視窗（分屏、平板直度）就會疊埋一齊，遮住對話泡泡。

**改法**：改成真 flex 底列（`#bottombar`）。**結構上就唔可能撞**，
唔係靠 margin 試出嚟。

### B6. 7 件貨排成 3+3+1 孤行

原設計每張單 3 正 + 4 干擾 = 7 件，3 欄排係 3+3+1，第七件黐住。
改為 **3 正 + 3 干擾 = 6 件 = 3+3**，兩行滿格，掃視負擔亦最低。

### B7. 雙擊會跨畫面誤觸，跳過最重要嗰個畫面（除錯巡檢發現）

**呢個係成個教材最隱蔽嘅 bug**，因為對老師嚟講「學生撠快咗」睇落好似學生問題。

兩個掣位置垂直重疊：

| 畫面 | 掣 | y 範圍 |
|---|---|---|
| 誠實確認 | ❌ 唔一樣 | 379 – 475 |
| 結果 | 🏅 下一張清單 / 睇我嘅獎狀 | 405 – 501 |
| 核對 | ✅ 有喎 | 446 – 530 |
| 核對 | ✅ 我睇清楚晒啦 | 453 – 537 |

**點解會出事**：學生雙擊時，第一次 `click` → `declare()` → `go("result")`，
但第二次 `mousedown` 已經喺**新畫面**落腳，命中「下一張清單」。
結果訊息（漏咗咩／多咗咩＋機器人回饋）被完全跳過。

核對畫面嗰組更嚴重：雙擊最後一次「有喎」→ 直接跳過**誠實確認畫面**，
學生根本冇答過，**連星星都攞唔到**。

**點解唔可以直接 disable 個掣解決**：到第二次 click 嗰陣，個掣已經喺另一個 `display:none` 嘅畫面，
游標下面根本唔係佢，disable 咗都冇用。

**改法**：加**輸入閘（input lock）**。`go()` 同 `answerCheck()` 之後 420ms 內，
喺 document capture phase 吞晒所有 click（早過任何目標 handler）。
閘門要 arm 喺**任何「學生一撠就換畫面內容」嘅動作**，唔淨係 `go()` ——
`answerCheck()` 會原地換走有／冇掣，一樣要 arm。

> 取捨：學生喺 420ms 內連撠兩下會漏一撠。
> 但動效本身已經 480–550ms，即係學生喺動畫未完時根本睇唔清新畫面有咩掣。
> 損失 = 撠多一下；收益 = 唔會跳過教學環節。對中度智障學生呢個 trade 非常值。

**驗證**：`double_click` 落「唔一樣」，之後仍然停喺結果畫面，掣仍然係「睇我嘅獎狀」而唔係已跳去證狀。

### B8. 證狀畫面打名會誤開老師面板

老師記錄面板有 `T` 鍵快捷鍵，但係 global `keydown` **冇檢查事件來源**。

學生／老師喺證狀打「Timothy」「Tony」呢類名，每撳一個 `t` 就彈出面板
（`position:fixed; inset:0` **完全遮住張證狀**），而個 `t` 又照樣入咗個欄 —— 名打歪咗，畫面仲俾個面板擋住。

**改法**：`e.target.closest("input, textarea, select, [contenteditable]")` 就直接 `return`。
同時將 `Escape` 改成 `return` 提早離開，令面板可以喺輸入框入面正常閂。

### B9. 列印出嚟嘅證狀上面有輸入格同按鈕

`@media print` 只做咗畫面層級嘅隱藏（`.screen:not(#s-cert)`），
但**證狀畫面將「證狀本身」同「做證狀用嘅控制項」擺喺同一層**：
`#cert`（要印）＋ 姓名 `<input>`（唔應該印）＋ 🔄 重新開始掣（唔應該印）＋「按此畫面可直接列印」提示。

印出嚟會係一張證狀上面多一個可填寫嘅輸入格同一粒掣。

**改法**：加 `c-edit` / `c-hint` class，print block 隱藏
`#s-cert .c-edit, #s-cert .c-hint, #s-cert > #btnRestart`。

### B10. 「複製記錄」嘅後備方案係空操作

```js
catch(e){ $("#teacherOut").select?.(); say("請手動複製下面文字。","think"); }
```

`#teacherOut` 係 `<pre>`，**`<pre>` 根本冇 `.select()` 方法**（只有 `<input>` / `<textarea>` 有）。
所以 clipboard API 一旦失敗（`file://`、非secure context、文檔失焦），
呢個「後備方案」乜都冇做 —— 老師見到「請手動複製」，但啲字根本冇被選中。

**改法**：用 `Range` + `Selection` API 真係選中 `<pre>` 內容，再試 `document.execCommand("copy")`；
兩樣都失敗先提示老師用 ⌘A。

## 🔵 C 級：跨學生污染（已修）

### C1. 進度持久化會污染下一個學生

原本用 `sessionStorage` 保存星星同記錄。問題：**課室會連續畀多個學生用同一個分頁**，
第二個學生會見到第一個學生嘅星星，出現「進度條話第 1 單，但已經有 2 顆星」嘅矛盾畫面。

**改法**：**完全唔做持久化**。每次開頁 = 新一節。

> 取捨：中途意外重載會失去進度。
> 但一節課 10-20 分鐘，唔重載；重載嘅代價 ≪ 跨學生污染嘅代價。

老師記錄只留喺記憶體，用完即場複製走（老師記錄面板有「複製文字」）。

## ⚪ D 級：刻意唔做嘅嘢

| 唔做 | 原因 |
|---|---|
| 自動修正（系統幫學生改返啱） | 原計劃已定：學生要自己睇完先決定。自動修正會消滅誠信練習 |
| 倒數計時 / 扣分 | 原計劃已定：無壓力 |
| 排名 / 百分比 | 「完成任務就有星星」，任何人都可以攞晒 3 顆。排名會製造「我輸咗」嘅感覺 |
| 圖卡上印「清單 ✓ / 干擾」標記 | **印咗等於印咗答案**。學生剪出嚟就見到，边樣應該擺去右邊 |
| 每項即時對錯 | 見 A3 |
| 學生名喺畫面自動帶入 | 資私 + 撞名。用證狀畫面手動輸入就夠 |

## 一句總結

原計劃最大嘅問題唔係內容，係**「即時反應」呢 4 個字**。

「即時反應」對吸引注意力有用，但對呢個教材係反效果 ——
學生注意力係用嚟**自己核對**，唔係用嚟捉系統提示。

所以改法唔係減少反應，而係**把反應全部推遲到學生已經答完之後**。
遊戲化（星星、音效、動畫）全部保留，一個都冇刪。
